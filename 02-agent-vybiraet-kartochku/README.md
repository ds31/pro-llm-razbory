# 02 · Агент теперь покупает в чате — кого он выберет?

Рубрика: Как читать AI. Статья: https://pro-llm.ru/blog/agent-pokupaet-v-chate-kogo-vyberet.html

13 октября 2026 года Shopify открыл Shop MCP (`https://mcp.shop.com/`): любой MCP-агент ищет по каталогу, собирает корзину и платит через Shop Pay. «Подключиться к агентам» больше не преимущество — выигрывает тот, кого агент выберет. А выбирает он по данным карточки: жёсткие фильтры — цвет, размер, пол, цена с валютой, рейтинг с минимальным числом отзывов, страна доставки, наличие — отсекают товары с пустыми полями до того, как модель что-то «решит».

Пакет показывает это дважды: на живом Shop MCP (какие поля видит агент и сколько товаров отсекает один фильтр) и на синтетическом каталоге вымышленной сети одежды, обуви и товаров для дома (сколько подходящих товаров агент не покажет и какими полями это чинится). Плюс чек-лист, чтобы проверить свои карточки.

## Запуск одной командой

```bash
uv run razbor02 all
```

Что нужно заранее: [uv](https://docs.astral.sh/uv/) и Python 3.11+ (uv поставит сам). Ключи API не нужны: Shop MCP открыт для анонимного поиска. Без сети или с `--offline` пакет берёт снимок ответов Shop MCP от 17.10.2026 из `eval/fixtures/`.

`all` = три шага, каждый можно запустить отдельно:

| Команда | Что делает | Куда пишет |
|---|---|---|
| `uv run razbor02 probe` | 4 запроса к живому Shop MCP: список инструментов, поиск как у агента, тот же поиск без фильтра и с фильтром по рейтингу | `eval/out/live/*.json`, сводка в консоли |
| `uv run razbor02 audit` | аудит `data/catalog.csv` по правилам `audit/rules.yaml` и пяти сценариям `eval/scenarios.yaml` | `eval/out/audit.json`, `eval/out/cards.csv` |
| `uv run razbor02 report` | HTML-отчёт на три экрана: `#tools`, `#search`, `#audit` | `eval/out/report.html` |

В конце `all` сверяет свой прогон с цифрами статьи: «прогон совпадает с eval/reference-run.json».

## Применить у себя

1. Выгрузите карточки в CSV с колонками как в `data/catalog.csv` (sku, title, category, product_type, color, sizes, target_gender, gtin, price, currency, available, ships_to, delivery_days, rating, rating_count, image_alt, tech_specs, …). Источник — что есть: учётная система, таблица, PIM, фид маркетплейса, выгрузка своего сайта.
2. Запустите аудит:

   ```bash
   uv run razbor02 audit --catalog путь/к/catalog.csv
   ```

   Если есть полная выгрузка из учётной системы с теми же колонками, добавьте `--erp путь/к/erp.csv`: тогда аудит покажет, какие поля достаточно скопировать в карточку, чтобы агент её снова увидел.
3. Откройте `eval/out/cards.csv`: балл готовности 0–100 и чего не хватает по каждой карточке. Сценарии под свой ассортимент — в `eval/scenarios.yaml`, правила и веса — в `audit/rules.yaml`.
4. Пройдите `checklist.md` — 14 проверок, каждая привязана к фильтру или полю агента.

## Как сверить цифры со статьёй

Цифры статьи — `eval/reference-run.json`; свой прогон — `eval/out/run.json` (пишется командой выше), отчёт — `eval/out/report.html`.

| Цифра | Значение | Поле в `eval/reference-run.json` |
|---|---|---|
| Инструментов в Shop MCP | 17 | `shop_mcp_snapshot.tools` |
| Атрибуты жёсткого фильтра | Color, Size, Target gender | `shop_mcp_snapshot.attribute_filters` |
| Карточек выдачи с рейтингом варианта | 5 из 10 | `shop_mcp_snapshot.card_fields` → `variants[].rating` |
| Проходят фильтр «рейтинг от 4 при 20+ отзывах» из 50 без фильтра | 1 | `shop_mcp_snapshot.filter_effect.base_meeting` |
| Товаров с фильтром, которых не было в выдаче без него | 49 из 50 | `shop_mcp_snapshot.filter_effect.replaced` |
| Подходящих товаров, которые агент покажет (5 сценариев) | 33 из 80 | `audit.visible_total`, `audit.pool_total` |
| Карточек, которых агент не увидит хотя бы в одном сценарии | 35 из 60 | `audit.lost_cards` |
| Из них чинятся заполнением 1–2 полей | 29 | `audit.fixable_1_2` (`audit.fixable`) |
| Топ-3 поля, из-за которых агент проходит мимо | страны доставки, наличие, GTIN | `audit.top_blockers` |
| Средний балл готовности | 77,5 из 100 | `audit.readiness.mean` |

Живой probe каждый раз возвращает свежую выдачу: число товаров и эффект фильтра в `eval/out/live/summary.json` могут отличаться от снимка, это нормально. Цифры статьи — по снимку.
