# CLAUDE.md — пакет 02

Отвечай по-русски.

## Что это

Пакет к разбору «Агент теперь покупает в чате — кого он выберет?» (рубрика «Как читать AI»). Две части: `probe` ходит в живой Shop MCP (`https://mcp.shop.com/`, stateless MCP 2026-07-28, без сессии и ключей) и показывает, какие поля карточки видит агент и сколько товаров отсекает один жёсткий фильтр; `audit` проверяет синтетический каталог вымышленной сети (одежда, обувь, товары для дома) по правилам, привязанным к фильтрам Shop MCP, и по пяти сценариям покупателя. `report` собирает HTML на три экрана для статьи.

## Команды

- тесты: `uv run pytest -q` (живой вызов — `uv run pytest -q -m live`, без сети пропускается)
- запуск: `uv run razbor02 all` (без сети: `--offline`)
- свой каталог: `uv run razbor02 audit --catalog файл.csv [--erp выгрузка_учёта.csv]`
- пересоздать синтетику: `uv run python data/make_catalog.py`
- обновить цифры статьи (только автору, после осознанной правки): `uv run razbor02 all --offline --write-reference`

## Устройство

| Путь | Что |
|---|---|
| `src/razbor02/mcp.py` | запрос к Shop MCP, разбор ответа, обезличивание, эффект фильтра |
| `src/razbor02/audit.py` | правила готовности, шаги фильтра сценария, пул, воронка, починка |
| `src/razbor02/synth.py` | генератор каталога: учётная система → карточка с потерянными полями |
| `src/razbor02/report.py` | HTML-отчёт: `#tools`, `#search`, `#audit` |
| `audit/rules.yaml` | правила и веса; у каждого — поле или фильтр Shop MCP |
| `eval/scenarios.yaml` | 5 сценариев покупателя в форме фильтров `search_catalog` / `lookup_catalog` |
| `eval/fixtures/` | обезличенный снимок ответов Shop MCP от 17.10.2026 |
| `eval/reference-run.json` | цифры статьи |
| `tests/` | тесты; в сеть ходит только тест с маркером `live` |

## Правила

1. Только синтетические данные; реальные каталоги, выгрузки и названия компаний не подключать.
2. Ответы Shop MCP перед записью в репозиторий — только через `anonymize_response` (магазины → `merchant-NN.example`, без `_gsid`). Повторно обезличивать уже обезличенный файл нельзя: имена `merchant-NN` сами станут токенами.
3. Правило аудита или сценарий меняется в одном месте (`audit/rules.yaml`, `eval/scenarios.yaml`) и вместе с тестом; у нового правила — ссылка на поле или фильтр Shop MCP в `shop_mcp`.
4. Карточка в синтетике только теряет поля учётной системы и никогда не придумывает новые значения — на этом держится подсчёт «чинится 1–2 полями».
5. Цифры статьи меняются только вместе с `eval/reference-run.json` и README; тест `test_reference_run_matches_fresh_offline_run` должен быть зелёным.
6. Секреты не нужны; `.env` не читать и не коммитить.
