# Эталонная архитектура: 1С → хранилище → Metabase → слой метрик → агент

Для компании на 1С без своей команды данных: один сервер, один инженер на внедрении, дальше всё работает по расписанию. Имена объектов 1С в пакете упрощены; в вашей конфигурации они свои.

```text
1С (рабочая база или ночная копия)
  │  расширение: HTTP-сервис выгрузки, ДатаИзменения при записи объекта
  │  02:00 — изменённое после прошлого запуска минус 2 часа; воскресенье — сверка сумм
  ▼
landing/<ночь>/  файлы обмена: Catalog_*, Document_*, AccumulationRegister_* + manifest.json
  │  K1 полнота против манифеста · K2 ключи · K3 ссылки на справочники
  ▼
raw   последняя версия каждого объекта (документы, строки, движения, справочники)
  ▼
stg   проведённые, без пометки удаления; справочники в аналитических именах
  ▼
mart  sales_daily · receipts_daily · stock_month_end · stock_current · stores · products
  │                                          │
  ├─► Postgres (схема mart) ─► Metabase      ├─► ворота качества, closed_through (пакет 05)
  │   дашборды для руководителя              ▼
  │                                        слой метрик metrics.yaml (пакет 01) ─► агент
```

## Слои и почему так

| Слой | Что хранит | Почему так |
|---|---|---|
| 1С | учёт | Источник правды. Данные забираются штатными средствами платформы: официальный FAQ по лицензированию запрещает обращаться к данным информационной базы в обход объектов 1С, в том числе на чтение (вопрос X.6-65). |
| Выгрузка | расширение с HTTP-сервисом | Доработки в расширении оставляют типовую конфигурацию на поддержке. Справочники — целиком каждую ночь (их мало), документы — по дате изменения, движения регистров — наборами по регистратору вместе с документом. |
| landing | файлы ночи + манифест | Архив того, что пришло. Манифест — сколько объектов, строк и какая сумма должны были прийти: без него обрезанный файл неотличим от тихого дня. |
| raw | последняя версия объекта | Загрузка идемпотентна: повторная выгрузка того же объекта заменяет его, а не дублирует. Поэтому перекрытие окна безопасно. |
| stg | правила учёта | «Проведён и не помечен на удаление» — одно место, где это записано. |
| mart | витрины | Пересобираются целиком каждую ночь: дорого читать 1С, а не считать витрины. Колонки — как у пакета 01, слой метрик подключается без правок. |
| Postgres + Metabase | отчёты | Витрины публикуются в схему `mart_load` и одной транзакцией подменяют `mart`. Metabase читает пользователем только для чтения; его служебная база — тоже Postgres, не встроенная H2. |
| Слой метрик + агент | вопросы текстом | `metrics.yaml` пакета 01: метрика, формула, разрезы, `closed_through`. Дату закрытия выставляют ворота пакета 05. |

## Инкремент: что ломает наивный способ

| Событие в 1С | По дате документа (окно 3 дня) | «Всё после прошлого запуска» | Дата изменения + перекрытие + сверка |
|---|---|---|---|
| Новый документ дня | видит | видит | видит |
| Правка документа прошлого месяца | не видит | видит | видит |
| Отмена проведения, пометка на удаление | не видит, если документ старше окна | видит | видит |
| Запись начата до 02:00, зафиксирована после | видит следующей ночью | теряет навсегда | видит следующей ночью (перекрытие) |
| Прямое удаление документа | не видит, если документ старше окна | не видит | исправляет сверка контрольных сумм в воскресенье |
| Правка справочника | видит (справочники целиком) | видит | видит |

Если в конфигурации уже есть план обмена с авторегистрацией нужных объектов, инкремент можно строить на нём: регистрация изменений — штатная служба платформы (ИТС, «Способы регистрации изменений данных в механизмах обмена данными»). Сверка контрольных сумм нужна и тогда.

## Где ломается

- **Нагрузка на 1С.** Полная выгрузка каждую ночь читает всю историю; на синтетике объёма L — 7,2 млн строк и 1,79 ГБ файлов за ночь против 11,7 тыс. строк у инкремента с перекрытием (`eval/reference-run.json`). Если ночное окно короткое, выгружать с ночной копии базы, а не с рабочей.
- **Тихие потери.** Инкремент без перекрытия и сверки расходится с 1С молча: отчёт не падает, просто цифры прошлых месяцев «плывут». Ловит только сверка контрольных сумм с источником.
- **Битый пакет.** Обрезанный файл или повтор ключа — пакет отклоняется целиком, водяной знак не двигается, следующая ночь забирает всё заново.
- **Обновление конфигурации.** Новые реквизиты в 1С появляются в файлах; загрузчик берёт только известные колонки (`dwh.COLUMNS`), остальное игнорирует до правки — сознательно.
