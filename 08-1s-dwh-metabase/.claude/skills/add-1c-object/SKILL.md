# Новый объект 1С в выгрузке и хранилище

1. Решить способ выгрузки: справочник — целиком каждую ночь; документ — по дате изменения с перекрытием; движения регистра, подчинённого регистратору, — наборами вместе с изменёнными документами; независимый регистр сведений — целиком или по периоду.
2. Источник (`src/razbor08/source.py`): таблица в схеме `ib`, генерация истории и события дня в `advance`, файл в `export` с полями как в стандартном интерфейсе OData (`Ref_Key`, `DataVersion`, `DeletionMark`, `Posted`, табличная часть массивом). В манифест — количество объектов, строк и контрольную сумму.
3. Хранилище (`src/razbor08/dwh.py`): колонки в `COLUMNS`, таблица в `raw`, проверка K1 против манифеста, K3 — ссылки на справочники того же пакета.
4. Витрина — в `marts.sql`; правило учёта (что считать проведённым) — в `stg`, одно место.
5. Эталон (`truth.py`): та же цифра прямо по источнику; `compare` — сверка.
6. Тест на каждый шаг: объект выгружается, K1 ловит обрезанный файл, витрина сходится с эталоном после правки задним числом и после удаления.
7. Никаких реальных имён и схем таблиц заказчика: объект называется по смыслу, данные синтетические.
