# Разобрать прогон

1. Прочитать `eval/out/summary.json`: точность, цена и время на вопрос по вариантам, разбивка `by_trap`.
2. Из `eval/out/results.jsonl` выбрать неверные ответы; для каждого — ловушка, `stop`, последний `run_sql` или `query_metric` из трассы.
3. Причину назвать одной фразой: «сложил остатки трёх месяцев», «взял октябрь как последний месяц», «join с raw.products».
4. Сравнить с `eval/reference-run.json`; расхождение больше допуска — показать трассы из `eval/out/report.html` (якорь `#trace-<id>-<вариант>`).
5. Ошибки B — сигнал о платформе: дописать описание метрики, правило или подсказку шлюза, а не менять эталон.
