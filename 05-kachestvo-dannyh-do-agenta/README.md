# 05 · Откуда агент знает, что месяц закрыт? Качество данных до агента

Рубрика: Платформа под агентом. Статья: https://pro-llm.ru/blog/kachestvo-dannyh-do-agenta-mesyac-zakryt.html

В [пакете 01](../01-agent-vret-v-cifrah) агент через слой метрик отвечал верно, потому что правило «|qty| ≥ 1000 — ошибка сканера» и дата `closed_through: 2026-09-30` были записаны в платформе руками. Этот пакет показывает, откуда они берутся на живых загрузках. Октябрь 2026 приходит файлами — магазин × день, снимок остатков, справочник — с девятью типами дефектов и известной правдой и идёт к агенту тремя путями: без ворот (месяц закрыт по календарю), с правилами пакета 01 в слоях (закрыт по снимку остатков) и через ворота — SQL-правила на каждой загрузке, карантин и закрытие месяца по чек-листу. Всё детерминированно и без LLM: ответы считают эталонные запросы слоя метрик пакета 01.

## Запуск одной командой

```bash
uv run razbor05 all
```

Нужен только [uv](https://docs.astral.sh/uv/); ключ API не нужен. Около пяти минут на 8 ядрах; быстрее — `uv run razbor05 all -n 20`. Отчёт — `eval/out/report.html`.

Другие команды:

```bash
uv run razbor05 rules                                   # паспорта правил
uv run razbor05 showcase --defect kopecks               # один дефект через три пути
uv run razbor05 replay --defect all --until 2026-11-06  # ворота утро за утром
uv run razbor05 close --defect all --as-of 2026-11-03   # чек-лист закрытия октября на утро
uv run razbor05 agent --offline                         # агент B: эталонные запросы вместо модели
```

Агент B пакета 01 через API — платно, около $0,22 за 14 ответов:

```bash
export ANTHROPIC_BASE_URL=https://openrouter.ai/api ANTHROPIC_AUTH_TOKEN=<ключ OpenRouter>
uv run razbor05 agent --only Q23          # пробный: один вопрос, два режима
uv run razbor05 agent                     # полный
```

## Что внутри

| Путь | Зачем |
|---|---|
| `rules/R*.sql`, `rules/C01_*.sql` | правила качества: паспорт (severity, action, fix, why) и SELECT нарушений |
| `rules/close/K*.sql` | чек-лист закрытия месяца |
| `src/razbor05/gate.py`, `close.py` | ворота: stage → правила → слой core или карантин; закрытие и `closed_through` |
| `src/razbor05/feed.py`, `defects.py` | поток загрузок поверх истории пакета 01; дефекты с правдой отдельно |
| `src/razbor05/modes.py`, `questions.py` | три пути к агенту; вопросы через слой метрик пакета 01 |
| `src/razbor05/experiment.py`, `report.py`, `cli.py` | сценарии, отчёт, команда |
| `src/razbor05/agent_check.py` | агент B пакета 01: календарь против ворот |
| `eval/` | критерий «прошёл», прогоны автора |
| `CLAUDE.md`, `.claude/skills/` | контекст и скиллы: `add-quality-rule`, `close-month`, `explain-quarantine` |
| `schemes/` | исходники схем статьи |

Пакет 01 подключён path-зависимостью: нужен весь репозиторий, а не одна папка.

## Как перенести на свои данные

1. Выписать дефекты своих загрузок за квартал: что пришло, что было на самом деле, кто исправил.
2. На каждый — правило в `rules/` (скилл `add-quality-rule`) и тест: ловит свой дефект, молчит на чистом потоке.
3. Записать свой чек-лист закрытия в `rules/close/`: кто что обязан прислать.
4. Подменить `feed.py` своими файлами в схеме `stage`, а витрины — своими (`layers.sql`).
5. Отдать агенту `closed_through` от ворот.
