# Добавить правило качества

1. Назвать дефект и его правду: что приходит в файле, что было на самом деле, что сломается у агента. Если дефект можно описать только «на глаз», правило не писать — сначала договориться о контрольной сумме с источником.
2. Решить паспорт:
   - `severity: block`, `action: drop` — строка-мусор, обратно её не ждут (ошибка сканера, повтор чека);
   - `severity: block`, `action: hold` — строка настоящая, но неверная; `fix: resend` (исправленный файл), `wait` (справочник), `reopen` (человек);
   - `severity: warn`, `action: pass` — эвристика, у которой бывают ложные срабатывания; строка проходит, нарушение в журнале.
3. Написать тест в `tests/test_gate.py`: дефект в `defects.py` (функция, которая портит поток и не трогает правду) и проверка, что правило его ловит, а на чистом потоке (`test_clean_stream_no_violations_and_closes_on_snapshot_day`) молчит.
4. `uv run pytest tests/test_gate.py -q` — новый тест падает.
5. Создать `rules/RNN_<имя>.sql`: первая строка `-- RNN · Название`, затем `table`, `severity`, `action`, `fix`, `why`; тело — SELECT из `stage.*` (и при нужде `core.*`), который возвращает `load_id, row_no, detail` (для файла целиком — `row_no` = NULL).
6. Тесты зелёные; `uv run razbor05 showcase --defect clean` — ни одного срабатывания на чистом потоке. Если правило блокирует — проверить, что карантин снимается (`uv run razbor05 replay`), иначе месяц не закроется никогда.
