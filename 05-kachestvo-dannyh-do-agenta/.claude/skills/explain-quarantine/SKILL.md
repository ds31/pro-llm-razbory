# Разобрать карантин

1. `uv run razbor05 replay --defect <сценарий> --until YYYY-MM-DD` — утро за утром: файлы, принятые строки, нарушения по правилам, запросы исправленных файлов, пропущенные файлы, закрытие; внизу — карантин по правилам и статусам.
2. Статусы: `dropped` — отброшено навсегда (R01, R02); `held` — ждёт; `replaced` — заменено исправленным файлом; `released` — отпущено (пришла карточка).
3. По каждому `held` — правило, магазин, день и чего ждём: `fix: resend` → кому написать за файлом; `fix: wait` → справочник; `fix: reopen` → решение человека о закрытом месяце. Паспорт правила — первые строки `rules/<id>_*.sql` или `uv run razbor05 rules`.
4. Оценить, что задержано в рублях (сумма `amount` удержанных строк), и сказать, какие ответы агента это меняет: месяц не закроется, пока карантин за него не пуст.
5. Предупреждения (warn) строку не держат: R07 — карточка-дубль заменила старую, R08 — короткий файл; их проверить глазами и, если это дефект, попросить источник прислать файл заново.
