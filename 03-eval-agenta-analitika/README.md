# 03 · Как доказать, что AI-агент считает правильно?

Рубрика: Агент в проде. Статья: https://pro-llm.ru/blog/kak-dokazat-chto-ai-agent-schitaet-pravilno.html

Каркас eval для агента-аналитика, который отвечает руководителю числами. Вопрос записывается вместе с живым эталоном — запросом `check_sql` по сырым данным, а не числом. Каркас проверяет, что ловушка вопроса «кусает», гоняет агента с повторами и сравнивает прогоны до и после правки с кодом выхода для CI. Судья-LLM включён как сравнительный режим. На агенте и базе пакета [01](../01-agent-vret-v-cifrah) эксперимент сравнивает три способа проверки на одних и тех же ответах.

## Результат прогона автора

Агент — `claude-sonnet-5.5` из пакета 01: A пишет SQL по сырым таблицам, B работает через слой метрик. Всё — в `eval/reference-run.json`.

**Три способа проверки, 60 ответов (A и B, прогон 19.10.2026), 6 настоящих ошибок:**

| Проверяющий | Пропустил ошибок | Забраковал верных | Цена |
|---|---|---|---|
| живой эталон `check_sql`, ±0,5 % | 0 из 6 | 0 из 54 | $0 |
| судья `claude-haiku-5.5` без эталона | 4 из 6 | 1 из 54 | $0,04 |
| судья `claude-sonnet-5.5` без эталона | 4 из 6 | 0 из 54 | $0,62 |

Оба судьи пропустили одни и те же четыре ошибки — от строк-ошибок сканера, когда трасса агента внутренне согласована. Поймали они две ошибки про неполный октябрь, о которых агент сам написал в пояснении. В 15 вердиктах из 120 судья не сдал вердикт инструментом и был переспрошен со structured output (`via: json`).

**Дозагрузка по 10.11.2026 (октябрь закрыт), агент B, 6 вопросов про «последний месяц»:**

| Платформа | Верно по живому эталону | Записанное 10.10 число | SQL с датой внутри (как в пакете 01) |
|---|---|---|---|
| `closed_through` сдвинут | 6 из 6 | забраковало 5 верных | забраковал 5 верных |
| `closed_through` не сдвинут | 1 из 6 | приняло 5 неверных | принял 5 неверных |

**Повторы (30 вопросов × 3 прогона):** A — 24, 25 и 24 верных, pass@1 81,1 %, pass^3 76,7 %, плавают Q17, Q23, Q24. B — 30 из 30 трижды, pass^3 100 %.

**Ворота (`compare`):** из `layers.sql` убрано правило аномалий — регрессии Q14–Q18, код 1; дозагрузка без сдвига `closed_through` — регрессии Q19, Q20, Q21, Q23, Q24, код 1; повтор без правок — код 0.

Новые прогоны агента и оба судьи 21.10.2026 обошлись в $3,55 (цены OpenRouter на эту дату). Прогон B на 30 вопросах стоит $0,48, прогон A — около $0,79.

## Запуск одной командой

```bash
uv run razbor03 all --offline
```

Без ключа и бесплатно: команда собирает базы сценариев, пересчитывает все таблицы выше по ответам автора и сверяет их с `eval/reference-run.json`. Отчёт — `eval/out/report.html`. Нужен [uv](https://docs.astral.sh/uv/) и папка `../01-agent-vret-v-cifrah` рядом: пакет 01 подключён path-зависимостью.

Свой прогон через API — весь эксперимент заново, около $5:

```bash
export ANTHROPIC_BASE_URL=https://openrouter.ai/api ANTHROPIC_AUTH_TOKEN=<ключ OpenRouter>
uv run razbor03 all --max-usd 5
```

Без OpenRouter подойдёт `ANTHROPIC_API_KEY` и `--model claude-sonnet-5-5`. Прерванный прогон продолжается с места остановки (`eval/out/experiment.json`).

Отдельные шаги:

```bash
uv run razbor03 refs --scenario reload                      # эталоны и «ловушка кусает» на дозагруженных данных
uv run razbor03 run --variant B --only Q19,Q23              # пробный платный прогон на двух вопросах
uv run razbor03 check ref:reload-stale-B                    # проверить прогон живым эталоном
uv run razbor03 compare --old ref:base-B-1 ref:base-B-2 ref:base-B-3 --new ref:no-anomaly-rule-B; echo $?
```

`ref:<имя>` — прогон автора из `eval/reference-run.json`; свои прогоны лежат в `eval/out/runs/`.

## Как перенести на своего агента

1. Записать 30 вопросов своих руководителей в `eval/questions.yaml`: эталон — SELECT по сырым данным с правилами компании, мимо витрин, которыми пользуется агент.
2. Подключить агента: класс с методом `answer(question) -> Answer` и фабрика, которую передаёт `--agent mypkg.agent:make`.
3. `uv run razbor03 refs` — все ловушки кусают; `uv run razbor03 run --repeats 3` — pass^3 и плавающие вопросы.
4. Поставить `compare` шагом CI на правки промпта, модели, слоя данных и на дозагрузку.
