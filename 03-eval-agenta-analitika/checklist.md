# Eval агента в проде: что должно быть до запуска

Чек-лист для агента-аналитика, который отвечает руководителю числами. Каждый пункт — «да» или «нет».

## Набор вопросов

- [ ] 30+ вопросов так, как их задают руководители, а не так, как удобно агенту.
- [ ] У каждого вопроса — живой эталон: SELECT по сырым данным с правилами компании. Числа в файле не хранятся.
- [ ] Эталон считается мимо того, что проверяется: не через витрины и слой метрик агента.
- [ ] «Последний месяц», «на сегодня», «последний квартал» — через данные, без дат-литералов.
- [ ] У каждой известной ловушки (дубли, ошибки выгрузки, незакрытый период, разные определения) — шесть вопросов и запрос-ловушка, который даёт другое число. Проверка «ловушка кусает» — в тестах.
- [ ] Контрольные вопросы без ловушки — чтобы отличать поломку агента от поломки данных.
- [ ] Допуск записан и обоснован: деньги ±0,5 %, номера и счёт — точно.

## Прогон

- [ ] Агент сдаёт число, единицу и пояснение; трасса запросов сохраняется вместе с ответом.
- [ ] Ответ и вердикт разделены: прогон можно перепроверить другим проверяющим без нового прогона.
- [ ] 3 прогона перед первым запуском: pass@1 и pass^3, список плавающих вопросов.
- [ ] Цена и время ответа — в каждом прогоне.

## Ворота

- [ ] Сравнение прогонов до и после с кодом выхода — шаг CI.
- [ ] Ворота стоят на правке промпта, смене модели, правке слоя данных и на дозагрузке данных.
- [ ] Регрессия блокирует правку; плавающий вопрос виден в отчёте.
- [ ] Порог «прошёл» записан до прогона, а не после.

## Судья-LLM

- [ ] Судья без эталона — только для вопросов, где эталона нет (текст, тон), и с выборочной проверкой человеком.
- [ ] Для числовых ответов судья не заменяет эталон: в прогоне автора лучший судья пропустил 2 ошибки из 6 и отверг 6 верных ответов.
