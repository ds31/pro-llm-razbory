# Разобрать неверный ответ

1. `uv run razbor03 check <прогон>` — список ERR: ответ агента и живой эталон.
2. Открыть ответ в JSON прогона (`answers[].trace`): последний `run_sql` или `query_metric` перед `final_answer`.
3. Пересчитать: `uv run razbor03 refs` — эталон и число ловушки. Ответ совпал с ловушкой — причина названа тегом вопроса.
4. Не совпал ни с чем — сравнить период, фильтры и формулу запроса агента с `check_sql`; выполнить запрос агента на базе сценария (`data/<сценарий>.duckdb`, только чтение).
5. Причина — одной фразой: «взял неполный октябрь», «в витрине остались строки-ошибки сканера», «доля от выручки с ошибками сканера».
6. Где чинить: правило очистки — в слое данных; определение — в слое метрик; понимание вопроса — в описании инструмента или метрики. Эталон меняется, только если ошибся сам `check_sql`, — с тестом.
7. Судья-LLM не заменяет разбор: его вердикт без эталона — мнение, не проверка.
