# Сравнить прогоны — ворота перед правкой

1. До правки должно быть 2–3 прогона на тех же вопросах (`uv run razbor03 run --repeats 3 …`): один прогон не отличает регрессию от плавающего вопроса.
2. После правки — прогон затронутых вопросов: `--tag <ловушка>` или `--only Q14,Q16`. Платно: сначала один-два вопроса, полный прогон — по просьбе человека.
3. `uv run razbor03 compare --old <до…> --new <после…>`; прогоны — пути к `eval/out/runs/*.json` или `ref:<имя>` из прогона автора.
4. Код выхода 1 — правку не пропускать. Регрессия — вопрос, который был верен во всех старых повторах, а в новых — нет. Плавающие до правки вопросы в отчёте видны, но не блокируют.
5. Для CI — та же команда шагом пайплайна; `--allow N` — только по решению человека, с причиной в описании правки.
6. Каждую регрессию разобрать скиллом `explain-failure`; чинить платформу или промпт, а не эталон.
