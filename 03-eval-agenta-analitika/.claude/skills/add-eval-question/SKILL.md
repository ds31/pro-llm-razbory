# Добавить вопрос eval

1. Вопрос — так, как его задаёт руководитель: период, разрез, единица ответа («в рублях», «в штуках», «номер магазина»).
2. `check_sql` — один SELECT по сырым данным с правилами компании. Не через витрины и не через слой метрик агента: эталон не должен ломаться вместе с тем, что проверяет.
3. Относительное время («последний месяц», «последний квартал», «на сегодня») — только через данные: `(SELECT max(date_trunc('month', snapshot_date)) FROM raw.stock)`. Дата-литерал устареет при первой дозагрузке, тест `test_no_date_literals_in_relative_questions` это стережёт.
4. `tag` — ловушка из списка `tags` в `eval/questions.yaml`; новая ловушка — сначала строка в `tags`. Контрольный вопрос без ловушки — `tag: none` и без `trap_sql`.
5. `trap_sql` — как ошибается наивный запрос. Проверка: `uv run razbor03 refs` — у вопроса не должно быть пометки «ловушка не кусает». Сделать это и на дозагруженных данных: `uv run razbor03 refs --scenario reload`.
6. Номер, месяц, счёт — `tolerance_pct: 0`; деньги и штуки — допуск файла (±0,5 %). Допуск не подгонять под ответ агента.
7. `uv run pytest -q` — зелёный. Число в файл не записывать: эталон считается при каждой проверке.
