# Чек-лист прод-готовности агента 24/7

Агент готов работать круглые сутки, когда на каждый пункт есть ответ «да» и способ это проверить. Пункты 1–12 проверены прогоном пакета (`uv run razbor07 all`), тестами (`uv run pytest -q`) и хаос-тестом шаблона (`deploy/chaos.sh`); в колонке «Где в шаблоне» — место, с которого можно начать у себя.

## Приём задач

| # | Пункт | Как проверить | Где в шаблоне |
|---|---|---|---|
| 1 | API не зовёт модель: принимает задачу, кладёт в очередь и отвечает 202 за миллисекунды | время ответа API не зависит от модели; в пик клиент не ждёт таймаута | `src/razbor07/api.py` |
| 2 | У задачи есть ключ идемпотентности от клиента (магазин + вопрос + дата, id сообщения бота), повтор с тем же ключом возвращает ту же задачу | отправить один запрос дважды — одна задача (`razbor07 load --resend-share 0.5`) | `Queue.enqueue`, заголовок `Idempotency-Key` |
| 3 | Очередь переживает рестарт процесса и контейнера: задачи лежат в базе на томе, а не в памяти | `docker compose restart` посреди нагрузки — ни одна задача не пропала | том `queue` в `deploy/docker-compose.yml` |

## Исполнение

| # | Пункт | Как проверить | Где в шаблоне |
|---|---|---|---|
| 4 | Задачу берут в аренду и продлевают её, пока работают; аренда истекла — задачу забирает другой воркер | `kill -9` воркера посреди задачи — задача доделана другим (`tests/test_live.py`) | `Queue.claim`, `Queue.heartbeat`, `Worker._beat` |
| 5 | Таймаут на каждом вызове модели — десятки секунд, а не 10 минут SDK по умолчанию | зависший вызов отпускает воркер через таймаут (профиль `hang`) | `Config.call_timeout`, `Worker.execute_call` |
| 6 | Ретраи задачи — с экспонентой и джиттером, с учётом `retry-after`, с потолком попыток | после N попыток задача в dead-letter, а не в бесконечном цикле | `queue.backoff`, `Config.max_attempts` |
| 7 | Ошибки делятся на повторяемые (429, 529, таймаут, обрыв) и нет (400, битый вход): вторые сразу в dead-letter | профиль `poison`: битые задачи не жгут попытки и токены | `fakellm.RETRYABLE`, `Queue.fail` |
| 8 | Воркеров столько, сколько выдерживает лимит запросов к модели, а не сколько выдержит сервер | 429 в пике не растут лавиной; воркеры × вызовов в минуту на воркер ≈ лимит | `deploy.replicas`, `Config.workers` |

## Побочные эффекты

| # | Пункт | Как проверить | Где в шаблоне |
|---|---|---|---|
| 9 | Каждый необратимый шаг (письмо, сообщение, заказ, запись во внешнюю систему) идёт с ключом идемпотентности, производным от ключа задачи | повтор задачи после письма — письмо не уходит второй раз (`send_deduped` в трассе) | `Send.idem_key`, `SqliteMailGateway` |
| 10 | Если внешняя система ключи не принимает — журнал отправок у себя: проверить «уже отправлено» перед отправкой, записать сразу после | хаос-тест: `CHAOS_KILL_P=0.1`, дублей писем 0 | `deploy/chaos.sh` |

## Процесс и деплой

| # | Пункт | Как проверить | Где в шаблоне |
|---|---|---|---|
| 11 | `restart: unless-stopped`, `init: true`, лимит памяти: упавший процесс поднимается сам | `docker inspect … RestartCount` после хаос-теста > 0, задачи доделаны | `deploy/docker-compose.yml` |
| 12 | Healthcheck у API (отвечает и видит очередь) и у воркера (файл жизни свежее минуты) | `docker compose ps` — `healthy`; зависший воркер — `unhealthy` | `/healthz`, `razbor07 health` |
| 13 | SIGTERM: воркер доделывает задачу и выходит; `stop_grace_period` больше самой долгой задачи | `docker compose stop worker` посреди задачи — задача `done` (`tests/test_live.py`) | `Worker.run`, `stop_grace_period` |
| 14 | Секреты — из окружения или менеджера секретов, не из файла в образе и не из репозитория | `docker history`, `git grep` ключа — пусто | `environment` в compose |
| 15 | API наружу — только через reverse proxy с TLS, порт приложения слушает localhost | `ss -lntp` на сервере | `ports: 127.0.0.1:…` |

## Наблюдаемость

| # | Пункт | Как проверить | Где в шаблоне |
|---|---|---|---|
| 16 | Структурный журнал: одна строка JSON на событие, в каждой — ключ задачи, попытка, воркер | `razbor07 trace --task <ключ>` собирает историю задачи целиком | `src/razbor07/trace.py` |
| 17 | У каждого вызова модели в журнале — шаг, исход, время, токены и цена | сумма `cost_usd` по задаче = её цена | событие `call` |
| 18 | Каждая начатая попытка кончается событием: `done`, `retry_scheduled`, `dead` или `lease_expired` | метрика «трасса до конечного статуса» = числу задач | `metrics["trace_complete"]` |
| 19 | Мониторинг: глубина очереди, возраст самой старой задачи, размер dead-letter, доля 429 | `GET /stats`; тревога, если возраст старше SLA или dead-letter растёт | `api.py /stats` |
| 20 | Журналы ротируются: `max-size` и `max-file` у драйвера логов | диск сервера через месяц | `logging` в compose |
