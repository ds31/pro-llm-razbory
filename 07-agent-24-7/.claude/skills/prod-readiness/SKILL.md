# Прод-готовность агента

1. Открыть `checklist.md` пакета. Для каждого из 23 пунктов найти в коде пользователя место, которое его выполняет, и ответить «да / нет / не применимо» с путём к файлу и строке. «Да» без места в коде не ставить.
2. Начать с пунктов 1, 2, 9: синхронный вызов модели из обработчика HTTP, отсутствие ключа задачи и необратимый шаг без ключа — источники потерь и дублей в прогоне пакета (`eval/reference-run.json`: наивная схема потеряла 180 задач из 1 000, очередь без ключей дала 40 дублей).
3. Выписать все необратимые шаги агента: письма, сообщения, заказы, записи во внешние системы. Для каждого — какой ключ идемпотентности и кто его проверяет (внешний API с `Idempotency-Key` или свой журнал отправок).
4. Посчитать воркеры под лимит модели: вызовов на задачу × задач в минуту в пике против лимита запросов в минуту тарифа. Если пик не помещается — назвать p95 в пике прогоном `razbor07 night` со своими цифрами (скилл `chaos-night`).
5. Итог — таблица «пункт → да/нет → где исправить» и три первых исправления по убыванию риска: потери, дубли, слепые зоны журнала.
