# 07 · Почему AI-агент в проде теряет задачи и пишет клиенту дважды?

Рубрика: Агент в проде. Статья: https://pro-llm.ru/blog/agent-24-7-teryaet-zadachi-i-pishet-dvazhdy.html

Агент вымышленной розничной сети отвечает магазинам на вопросы и отправляет ответ письмом. В демо он работает: вопрос — три вызова модели — письмо. Этот пакет прогоняет через него «ночь» из 1 000 вопросов со сбоями, которые случаются в проде: лимит запросов в утренний пик (429), перегрузка провайдера (529), зависший вызов, обрыв посреди ответа, kill -9 процесса, потерянный ответ API и битые задачи. Три конфигурации: наивная (агент синхронно в обработчике API, SDK по умолчанию), очередь с ретраями без идемпотентности и прод (очередь, аренда с продлением, ретраи с backoff, dead-letter, ключи идемпотентности, таймауты, трасса на каждую задачу). Живой LLM не нужен: фейковая модель со сбоями по профилю, виртуальные часы, всё детерминированно по seed. Тот же код агента и очереди запускается в `docker compose` — шаблон деплоя и хаос-тест в `deploy/`.

## Результат прогона автора

22.11.2026, `eval/reference-run.json`, seed 48, 1 000 задач за 4 часа, 30 % — в 10-минутный пик:

| | Наивная | Очередь без идемпотентности | Прод |
|---|---|---|---|
| Доставлено ответов | 820 | 994 | 994 |
| Потеряно: ответа нет, в dead-letter нет | **180** | 0 | **0** |
| Дубли: на вопрос ответ пришёл дважды и больше | **22** | **40** | **0** |
| В dead-letter, с причиной | — | 6 | 6 |
| p50 до ответа | 7,6 с | 9,7 с | 9,6 с |
| p95 до ответа | 36,6 с | 9,2 мин | 8,9 мин |
| Трасса до конечного статуса | 990 из 1 000 | 1 000 | 1 000 |
| Вызовов модели на доставленный ответ | 3,19 | 3,20 | 3,18 |

100 ночей с seed 1000–1099: наивная теряла задачи и дублировала письма в каждой ночи (потеряно 153–209 за ночь, дублей 12–38); очередь без идемпотентности — ни одной потери, дубли в каждой ночи (24–65); прод — ни одной потери и ни одного дубля за 100 ночей, в dead-letter 1–11 задач за ночь (без ответа — только битые).

Хаос-тест шаблона в docker compose (`deploy/chaos.sh`, лог — `eval/docker-chaos-run.txt`): 100 задач, 12 из них отправлены повторно с тем же ключом, воркер убивает себя kill -9 сразу после письма примерно в 10 % задач; контейнеры воркеров перезапускались 17 раз — все 100 задач `done`, 100 писем, дублей 0.

## Запуск одной командой

```bash
uv run razbor07 all
```

Нужен только [uv](https://docs.astral.sh/uv/); ключ API не нужен, зависимостей нет — стандартная библиотека Python 3.10+ (в образе docker — 3.13). Цена вызова в трассе считается по примерному тарифу $3 / $15 за млн входных / выходных токенов (`PRICE_IN`, `PRICE_OUT` в `src/razbor07/trace.py`) — подставьте тариф своей модели. Около минуты на 8 ядрах; быстрее — `uv run razbor07 all -n 10`. Отчёт — `eval/out/report.html`.

Другие команды:

```bash
uv run razbor07 night --profile all              # одна ночь во всех конфигурациях
uv run razbor07 night --profile kill9 --config prod
uv run razbor07 faults                           # сбои по одному: потеряно, дубли, p95
uv run razbor07 trace --config prod              # трасса задачи, пережившей kill -9 (JSON Lines)
uv run pytest -q                                 # тесты, около минуты
```

Шаблон деплоя (нужен Docker):

```bash
docker compose -f deploy/docker-compose.yml config --quiet   # проверить шаблон
./deploy/chaos.sh                                            # поднять, 100 задач, kill -9, проверка, снести
```

## Как перенести на свой агент

1. Пройти `checklist.md` по своему агенту (скилл `prod-readiness`): на каждый пункт — «да» и как проверено.
2. Подставить свои цифры в `Night` и `Faults` (`src/razbor07/sim.py`, `fakellm.py`): задач в сутки, пик, лимит запросов в минуту своего тарифа, вызовов модели на задачу — и прогнать `razbor07 night` (скилл `chaos-night`). p95 в пике покажет, сколько воркеров и какой лимит нужны под ваш SLA.
3. Найти в своём агенте каждый необратимый шаг — письмо, сообщение, заказ, запись в чужую систему — и дать ему ключ идемпотентности от ключа задачи.
4. Заменить фейковую модель в `Worker.execute_call` вызовом своего SDK с таймаутом десятки секунд, а агента в `agent.py` — своим циклом tool use.
5. Перед релизом — `deploy/chaos.sh` на своём образе.
